# AGENTS.md - QuickerNesHawk core for Chimera

This repository is QuickerNesHawk, a header-only C++ translation of BizHawk's
NesHawk (NES and Famicom Disk System), and its port to Chimera, a frontend
for tool-assisted speedruns. It produces one file,
`quickerneshawk.chimeraCore`: the emulator built as a sandboxed guest
(`core.wbx`) plus the declarations Chimera reads. Chimera's sandbox, miniBox,
runs that guest on Linux and on Windows. The GitHub repository is
`chimera-core-neshawk`; the core's id is `quickerneshawk`. The scripts say
"miniHawk" where they mean the Chimera checkout.

## Layout

- `source/` - the emulator: header-only C++17, translated from BizHawk.
- `waterbox/waterbox.cpp` - the guest ABI layer over the emulator.
- `waterbox/waterbox.config` - what Chimera is told about the machine:
  video, audio, the controller, the two machines, settings, firmware.
- `waterbox/file_slots.json` - the files a project asks the user for.
- `waterbox/default_keybinds.json` - default key bindings.
- `waterbox/package-licenses.json` - the licence terms the package carries.
- `waterbox/nesPalettes.hpp`, `nes6502Disasm.hpp`, `audioKernel.hpp` -
  generated by `waterbox/tools/gen-*.py`.
- `waterbox/setup-guest.sh` - configures the guest build.
- `waterbox/build-package.sh` - builds and installs the package.
- `waterbox/run-gate.sh` - the core gate; `run-native.cpp`, `run-wbx.c` and
  `run-tooling.c` are its drivers.
- `waterbox/tests/run-frontend.sh` - the frontend gate, with its helpers.
- `waterbox/roms/sprilo.nes` - the free rom both gates use.
- `tools/` - standalone drivers (`cpuFuzz`, `nesReplay`, `stateTest`,
  `resyncReplay`) and `transliterate_cpu.py`.
- `test/` - the ROM-free 6502 regression and its golden trace.
- `harness/` - a C# oracle that runs genuine NesHawk. Run by hand.
- `meson.build` - a cross configure is the guest; a native configure is the
  reference, the drivers, the tools and the test.
- `.github/workflows/minihawk.yml` - the Chimera CI: core gate, frontend
  gate, publish. `ci.yml` builds the tools and runs the 6502 regression.
- `build/` - every build tree. Ignored by git.

## Set up the build environment

```sh
sudo apt-get update
sudo apt-get install -y --no-install-recommends meson ninja-build build-essential python3

CHIMERA=$HOME/chimera
[ -d "$CHIMERA" ] || git clone https://github.com/ToolAssisted-run/chimera.git "$CHIMERA"
git -C "$CHIMERA" submodule update --init extern/chimera-common-minibox
MB=$CHIMERA/extern/chimera-common-minibox

[ -f "$MB/build/meson-cpp/build.ninja" ] || meson setup "$MB/build/meson-cpp" "$MB" -Dguest_cpp=true
meson compile -C "$MB/build/meson-cpp"
```

This repository has no submodules. The first miniBox build downloads the GCC
source that matches the host gcc (about 84 MB) to build libstdc++ for the
guest. The frontend gate needs more: Chimera built with its window
(Chimera's `tools/ci-chimera.sh` builds it). See `docs/BUILDING.md`.

## Build

The shortest path to a package is one command. It builds miniBox and the
guest when they are missing, and writes
`$CHIMERA/build/Cores/quickerneshawk.chimeraCore`:

```sh
./waterbox/build-package.sh -r "$CHIMERA"

# the native reference and the guest, which the gates need
meson setup build/meson-native "-Dminibox_dir=$MB"
ninja -C build/meson-native
sh waterbox/setup-guest.sh -m "$MB"
ninja -C build/meson-guest core.wbx
```

## Install the core into Chimera

`build-package.sh -r "$CHIMERA"` installs it: `$CHIMERA/build/Cores/` is the
cores folder of a Chimera source checkout. For a release bundle, copy the
`.chimeraCore` file into the `cores` folder beside Chimera's program (or the
folder chosen in Tools > Core Manager... > Change folder...). Chimera downloads
nothing. Tools > Core Manager... lists the folder; Refresh List rescans it.

A package built by hand is stamped `<commit>+local` (`-dirty` when the tree
has changes) and is for testing. Only CI sets `CORE_VERSION` and publishes.

## Test before you commit

```sh
./waterbox/run-gate.sh                                          # the core gate
meson test -C build/meson-native                                # the 6502 regression
./waterbox/tests/run-frontend.sh --chimera-root "$CHIMERA"     # the frontend gate
```

The core gate must end with `0 failed`. It compares the sandboxed core with
the same sources built for the host (video, audio, lag, memory), round-trips
a savestate around every frame, and checks turbo, the tooling exports and
save data. Its `saveram` leg reports SKIP; that is expected.

The frontend gate needs Chimera built with its window (`$CHIMERA/build/meson-linux/source/ui/chimera`), the
installed package and `build/meson-native/run-native`. Every leg must report
PASS. CI publishes only when the core gate and the frontend gate are green.

## Rules of this repository

- There is no `extern/`, no submodule and no `patches/`. The emulator is
  this repository's own source: edit `source/` in place. Each header names
  the BizHawk file it was translated from; keep the two line-auditable.
- Do not hand-edit generated files. `source/mos6502x.hpp` is emitted by
  `tools/transliterate_cpu.py`; its header says to change the script and
  regenerate. The three generated headers in `waterbox/` come from
  `waterbox/tools/gen-*.py`.
- Determinism is the product. The guest must not read host time, host
  randomness or anything else that differs between runs, and a savestate
  must round-trip. The gate checks it; a change that breaks it is a bug.
- Both flavors compile the same sources with the same `core_args`
  (`meson.build`). The audio resampler is fixed point because the gate
  compares a glibc host build with a musl guest build; keep it so.
- Run the gate before committing. A new leg needs a negative control: break
  the thing it checks, watch it fail, and say so in the commit.
- `run-wbx` accepts a flag it does not know in silence and exits 0. A new
  leg must check for output that proves its flag was honoured.
- A fidelity change (a new board, a CPU fix) is verified against genuine
  NesHawk with `harness/`, by hand. The sandbox gate does not test fidelity.
- Never commit game files, BIOS or firmware. The only rom in the tree is the
  free-to-distribute `waterbox/roms/sprilo.nes`. Never add network access.
- Every component compiled into the package is declared in
  `waterbox/package-licenses.json`.
- Shell scripts stay executable (git mode 100755). CI runs them directly.
- New documentation is plain ASCII. Some older files (`README.md`,
  `waterbox/README.md`) are not; leave them unless asked.
- Commit messages: a type and an optional scope (`fix(gate):`,
  `feat(package):`, `docs(issues):`, `ci:`), then a full sentence that states
  the outcome, such as `fix(gate): a channel that is not there says so,
  instead of blaming the cart`. The body says why and what was measured. A
  fix for a reported problem cites `ToolAssisted-run/chimera#N`: problems
  with this core are reported in the Chimera repository.
- Do not edit `.github/workflows` unless the task is the workflow. A push
  or a pull request starts the Chimera workflow only when it touches
  `waterbox/`, `source/` or the workflow file.
